# CHANGELOG — аудит и продакшн-фикс qsim

## v0.4.0 — переносимость QASM, коррелированный шум, edge-case-фиксы

Четыре пункта, найденных при повторном аудите v0.3.0. Все закрыты
регрессионными тестами (19 новых: 3 в `test_bugfixes.py`,
16 в `test_features.py`); полный набор тестов пакета (120 тестов)
проходит целиком, включая все 101 тест из v0.3.0 без единого
изменения их поведения — за исключением двух тестов на конкретный
текст QASM-экспорта (`test_crx_export`, `test_toffoli_and_fredkin_export`),
которые обновлены под сознательно изменившийся (более переносимый)
формат вывода — см. пункт 1.

1. **`to_qasm()`: экспорт полагался на необязательные гейты `qelib1.inc`.**
   Самая первая/строгая версия OpenQASM 2.0 `qelib1.inc`
   (arXiv:1707.03429) содержит только `u1/u2/u3/cx/id/x/y/z/h/s/sdg/t/
   tdg/rx/ry/rz/cz/cy/ch/ccx/crz/cu1/cu3`. Гейты `sx`, `sxdg`, `swap`,
   `crx`, `cry`, `cswap` в неё НЕ входят (они есть только в отдельных
   расширенных дистрибутивах, например поставляемом с Qiskit) — экспорт
   схемы с этими гейтами по имени мог не загрузиться в инструменте со
   строгим `qelib1.inc`. Теперь такие гейты раскладываются в
   гарантированно присутствующий базовый набор:
   - `sx`/`sxdg` → `u3(±pi/2,-pi/2,pi/2)` (с точностью до ненаблюдаемой
     глобальной фазы — она не имеет значения для однокубитного гейта
     не под управлением);
   - `swap` → три `cx` (`cx(a,b); cx(b,a); cx(a,b)`);
   - `crx`/`cry` → `u1/cx/u3` и `ry/cx` соответственно (управляемые
     гейты — здесь разложение проверено на ТОЧНОЕ, а не с точностью до
     фазы, совпадение с полной 4x4 матрицей, поскольку относительная
     фаза между блоками control=0/control=1 физически значима);
   - `cswap` (Fredkin) → `cx(b,a); ccx(c,a,b); cx(b,a)`.

   Каждое разложение проверено численно (сравнение с независимо
   построенной эталонной unitary-матрицей) перед тем, как попасть в
   код — см. `TestQasmPortability` в `test_features.py`. `crz`, `ccx`,
   `cx`, `cy`, `cz`, `cu1` уже есть в самой первой версии `qelib1.inc` и
   по-прежнему экспортируются по имени, без изменений.

   Дополнительно исправлены два смежных пробела:
   - `control()`/`controlled_gate()` с пустым списком `controls`
     (полностью определённая, уже поддержанная на уровне `run()`/
     `draw()` операция — гейт без управления) раньше не совпадал ни с
     одним известным паттерном экспорта и бросал `CircuitError`;
     теперь экспортируется как обычный гейт на `targets`.
   - Управляемая фаза, добавленная через общий `control(Phase(phi), ...)`
     (а не через специализированный `cp()`), теперь тоже распознаётся и
     экспортируется как `cu1`.

   Без изменений (по-прежнему требует полной транспиляции и потому
   намеренно не поддержано, с понятным `CircuitError`): `u()`/U3,
   `control()`/`controlled_gate()` с произвольной пользовательской
   матрицей (кроме случая с пустыми `controls`, см. выше), `mcx()` с
   3+ controls.

2. **Шум: не было способа выразить корреляцию между двумя кубитами.**
   `NoiseModel`/`NoiseChannel` зашумляли кубиты только по отдельности —
   даже применяя один и тот же `NoiseChannel` к обоим кубитам
   двухкубитного гейта, результат по построению факторизуется
   (независимая ошибка на каждом кубите), что не может выразить,
   например, коррелированную деполяризацию CX (типичная физическая
   ошибка двухкубитного гейта — это одновременная случайная ошибка на
   ОБОИХ кубитах, разыгранная одним броском, а не двумя независимыми).
   Добавлены:
   - `TwoQubitNoiseChannel` — тот же приём quantum trajectories, что и у
     `NoiseChannel`, но операторы Крауса действуют на пару кубитов как
     единое 4-мерное целое; вероятности исходов считаются из
     приведённой 4x4 (а не полной 2^n x 2^n) матрицы плотности пары, тем
     же приёмом, что и `NoiseChannel.sample_and_apply`/
     `Simulator.bloch_vector`.
   - `correlated_depolarizing_channel(p)` — прямое двухкубитное
     обобщение `depolarizing_channel(p)` (та же twirl-параметризация,
     15 ненулевых комбинаций Паули P⊗Q вместо 3 для одного кубита).
   - `NoiseModel.add_two_qubit_channel(q0, q1, channel)` /
     `two_qubit_channel_for(q0, q1)` — канал регистрируется на
     неупорядоченную пару кубитов. Если для пары, задействованной в
     конкретном двухкубитном гейте (`'two'` или `'controlled'` с одним
     control и одним target), зарегистрирован такой канал, он ПОЛНОСТЬЮ
     заменяет собой независимый шум по отдельным кубитам для этой
     инструкции (не комбинируется с ним — иначе шум был бы учтён
     дважды). Многокубитные управляемые гейты (mcx и т.п., больше двух
     задействованных кубитов) по-прежнему зашумляются по отдельным
     кубитам — двухкубитные каналы для них не подбираются, это
     сознательное ограничение объёма (полноценный n-кубитный
     коррелированный шум потребовал бы 2^(2n)-размерных операторов).

3. **Мелкие edge-case'ы.**
   - `Simulator.sample(qubits=[...])` не проверял повторяющиеся индексы:
     `sample(qubits=[0, 0])` молча дублировал соответствующий бит в
     каждом ключе `counts` (например, `'00'` вместо `'0'` для
     однокубитного среза) без единого предупреждения о том, что
     результат, скорее всего, не то, что имел в виду вызывающий. Теперь
     бросает `QSimValueError`.
   - `Circuit.measure(q, cbit=...)` не проверял тип `cbit`: `cbit`
     документирован (`measured_labels()`) как строка или `None`, но
     `measure(0, cbit=42)` молча принимался — несоответствие типа
     обнаружилось бы не здесь, а где-то произвольно далеко ниже по
     потоку использования подписей как строк. Теперь проверяется явно
     (`QSimTypeError` для не-`str`/не-`None`).

4. **Типизация.** Добавлены аннотации типов для параметров и
   возвращаемых значений публичных методов `Circuit`, `Simulator`,
   `State` (внутренние приватные хелперы и без того короткие/локальные
   методы не тронуты — не критично для их читаемости).

## v0.3.0 — расширение возможностей

Восемь новых возможностей, реализованных поверх аудита из v0.2.0.
Каждая закрыта регрессионными тестами (`qsim/test_features.py`, 47
тестов); полный набор тестов пакета (`test_bugfixes.py` + `test_circuit.py`
+ `test_physics.py` + `test_features.py`, 101 тест) проходит целиком, в
том числе без единого изменения в уже существовавших тестах — все
добавления обратно совместимы.

1. **Единая иерархия исключений** (`qsim/_errors.py`): `QSimError` —
   общий корень, плюс `QubitError`/`GateError`/`ShotsError`/
   `CircuitError` для точечного перехвата. Каждое исключение qsim
   одновременно является и `QSimError`, и соответствующим встроенным
   типом (`TypeError`/`ValueError`) — весь существующий код с
   `except TypeError`/`except ValueError` продолжает работать без
   изменений; это чистое уточнение, а не breaking change.

2. **Параметризованные схемы** (`qsim/parameters.py`): `Parameter` —
   именованный символьный параметр для `rx`/`ry`/`rz`/`p`;
   `Circuit.parameters` — список несвязанных параметров;
   `Circuit.bind({param: value, ...})` — возвращает новую схему с
   подставленными значениями (можно частично, по объекту или по
   имени; сопоставление по объекту приоритетнее и надёжно различает
   разные параметры с одинаковым именем). `run()` на схеме с
   несвязанными параметрами бросает понятный `CircuitError` вместо
   падения где-то в недрах гейтов. Параметризация `u()`/U3
   сознательно не реализована.

3. **Общие Pauli-string expectation values** (`Simulator.expectation`):
   `<ψ|P|ψ>` для произвольной строки Паули (`'XZI'` и т.п.), без
   построения полной 2^n x 2^n матрицы — каждый однокубитный оператор
   строки применяется напрямую к тензору состояния. Дополняет уже
   существовавший `expectation_z` (частный случай для одного `Z`).

4. **Вектор Блоха одного кубита** (`Simulator.bloch_vector`): вычисляется
   из приведённой 2x2 матрицы плотности (partial trace по остальным
   кубитам), без построения полной матрицы плотности — корректно
   определён и для сцепленных состояний (тогда |вектор| < 1).

5. **Матрица плотности** (`State.density_matrix`): `rho = |ψ><ψ|` для
   анализа/обучения на малых n; сам `State` остаётся statevector-
   представлением (O(2^n) памяти) — это не альтернативный бэкенд.

6. **Модели шума** (`qsim/noise.py`): `NoiseChannel` на произвольных
   операторах Крауса (с проверкой TPCP при создании: sum K_i^dagger K_i
   == I), готовые каналы `depolarizing_channel`, `bit_flip_channel`,
   `phase_flip_channel`, `amplitude_damping_channel`, и `NoiseModel` для
   привязки канала ко всем кубитам или к конкретным. Реализовано через
   **quantum trajectories** (stochastic unraveling): на каждом
   зашумлённом месте для каждого shot заново разыгрывается конкретный
   Kraus-оператор — точная, а не приближённая техника, но требующая
   `Circuit.run(shots=..., noise=...)` — присутствие noise, как и
   mid-circuit measurement/reset, переводит `run()` на по-shot-ный путь.
   Полноценная эволюция общей матрицы плотности (O(4^n) памяти) не
   реализована — для statevector-бэкенда это неприемлемо уже при паре
   десятков кубитов. ВАЖНО: `depolarizing_channel(p)` использует
   "twirl"-параметризацию (Kraus: `sqrt(1-p)*I, sqrt(p/3)*{X,Y,Z}`), из-за
   чего `<Z>` базисного состояния после канала равна `1 - 4p/3`, а не
   `1 - p` — см. docstring функции.

7. **Именованные классические биты** (`Circuit.measure(q, cbit=name)`,
   `Circuit.measured_labels()`): позволяет подписать измеренные биты
   человекочитаемыми именами для последующей интерпретации `counts`, не
   меняя сам формат ключей `counts` (по-прежнему битовые строки по
   возрастанию индекса измеренного кубита).

8. **Экспорт в OpenQASM 2.0** (`Circuit.to_qasm()`): все фиксированные
   однокубитные гейты, `rx/ry/rz/p` (как `u1`), `cx/cy/cz/swap/cp` (как
   `cu1`), `crx/cry/crz`, `ccx`, `cswap`, `reset`, `measure`, `barrier`.
   Явно НЕ поддержано (бросает `CircuitError` с понятным сообщением, а
   не тихо теряет часть схемы): несвязанные `Parameter`, `u()`/U3,
   `control()`/`controlled_gate()` с произвольной пользовательской
   матрицей, управляемые гейты с более чем двумя controls — для всего
   этого нужна декомпозиция в базисные гейты (транспиляция), которая не
   реализована. Числовые параметры сериализуются с точностью `%.6g`
   (соответствующая подпись гейтов в `draw()` тоже повышена с `%.2f` до
   `%.6g` для консистентности) — не гарантирован побитовый round-trip.

9. **Опциональная визуализация** (`qsim/visualization.py`, НЕ
   импортируется автоматически из `qsim/__init__.py`, чтобы отсутствие
   matplotlib не влияло на возможность использовать сам qsim):
   `plot_histogram(counts)` и `plot_bloch(vector)`.

## v0.2.0 — аудит и продакшн-фикс

Все найденные проблемы были **воспроизведены на исходном коде**, затем
исправлены и закрыты регрессионными тестами (`qsim/test_bugfixes.py`).
Основная физика симуляции (`apply_single`/`apply_gate`/`apply_controlled`)
была сверена с независимо построенными эталонными матрицами
(`qsim/test_physics.py`) — ошибок в самой математике не найдено, но раньше
это вообще ничем не проверялось (в исходном `test_circuit.py` не было ни
одного теста на физическую корректность гейтов).

## Найденные и исправленные баги

1. **Валидация индексов кубитов пропускала дробные и булевы значения.**
   `Circuit.h(1.5)` и `Circuit.h(True)` успешно строились (`0 <= 1.5 < n`
   — истина в Python, `isinstance(True, int)` — тоже истина), а падали
   только при `run()`, глубоко внутри numpy, с не относящейся к делу
   ошибкой (`TypeError: 'float' object is not iterable`). Теперь тип
   проверяется явно и сразу в момент построения инструкции.

2. **`Circuit.__init__` не проверял тип `n_qubits`** (в отличие от
   `State.__init__`). `Circuit(2.5)` тихо принимался, ошибка
   всплывала позже и не по адресу. Исправлено: обе точки входа теперь
   используют одну и ту же функцию проверки.

3. **`Circuit.control()` не проверял повторяющиеся `controls` и
   `control == target`** — в отличие от `controlled_gate()`, у которой
   такая проверка была. Ошибка обнаруживалась только при `run()`,
   внутри `State.apply_controlled`. Теперь обе точки входа используют
   общую проверку сразу при построении схемы.

4. **Несогласованная (местами отсутствующая) валидация `shots`.**
   На "быстром" пути `run()` (без `reset`, без mid-circuit измерений)
   отрицательные/нецелые `shots` корректно отклонялись — проверка жила
   внутри `Simulator.sample()`. На "медленном" пути (есть `reset` или
   незавершающее измерение) проверки не было вовсе: `for _ in
   range(shots)` с отрицательным `shots` — пустой цикл, и функция молча
   возвращала `({}, None)`. `None` вместо `State` нарушает контракт
   `run(shots=...) -> (counts, state)`. Исправлено: `shots` теперь
   проверяется один раз в начале `run()`, до выбора пути.

5. **`State.amplitude(bitstring)` не проверял длину/алфавит строки.**
   `State(3).amplitude('1')` молча возвращала `vector[int('1',2)] ==
   vector[1]` — амплитуду совершенно не того базисного состояния,
   которое, скорее всего, имел в виду вызывающий, **без единой ошибки**.
   Слишком длинная строка падала с низкоуровневым `IndexError`. Теперь
   длина и алфавит строки проверяются явно; дополнительно метод стал
   принимать и целочисленный индекс напрямую.

6. **Пользовательские (не из встроенного реестра) матрицы гейтов в
   `Circuit.control()`/`controlled_gate()` не проверялись на
   унитарность.** Применение неунитарной матрицы молча портит
   нормировку состояния (воспроизведено:
   `State.apply_single(2*I, 0)` удваивает норму вектора состояния без
   единого предупреждения). Теперь пользовательские матрицы, переданные
   через `Circuit`, проверяются на унитарность в момент построения
   схемы. Низкоуровневый `State.apply_*` намеренно оставлен
   непроверяющим — он нужен и для не-унитарных операций (моделирование
   шума и т.п.).

7. **Продублированная константа `MAX_RECOMMENDED_QUBITS`** — определена
   независимо в `state.py` и `circuit.py`, риск рассинхронизации при
   правке только одного из файлов. Вынесена в `qsim/_common.py` как
   единый источник истины.

8. **Производительность: `final_state = state.copy()` вызывался на
   КАЖДОЙ итерации per-shot цикла** ("медленный" путь `run()`), хотя
   нужна только последняя копия — O(shots) лишних полных копий
   statevector. Копирование перенесено за пределы цикла.

9. **Дублирование логики в `Circuit.run()`**: два почти дословно
   одинаковых блока ("измерения терминальны" и "измерений нет вовсе")
   объединены в один метод `_supports_deferred_measurement()`.

10. **Вводящий в заблуждение комментарий в `state.py`** про
    "Qiskit-подобную конвенцию" в `apply_gate` — на деле используемая
    здесь конвенция (кубит 0 — старший бит) прямо противоположна
    little-endian конвенции Qiskit (кубит 0 — младший бит).
    Переформулировано, чтобы не вводить в заблуждение при интеграции.

11. **Встроенные гейты не имели самопроверки.** Опечатка в матрице
    фиксированного гейта осталась бы незамеченной до первого случая,
    когда кто-то заметил бы физически неверный результат. `gates.py`
    теперь проверяет унитарность всех встроенных гейтов один раз при
    импорте модуля.

## Что проверено и подтверждено корректным (не баг)

- Основная математика `apply_gate`/`apply_controlled` в `state.py`
  сверена с независимо построенными эталонными полными unitary-матрицами
  на случайных перестановках кубитов — совпадает с точностью до
  `1e-10` во всех прогонах. Конвенция индексации (кубит 0 — старший бит)
  используется последовательно во всём пакете.
- `gates.py`: матрицы `CNOT`, `CY`, `CZ`, `SWAP`, `CPhase` и все
  фиксированные однокубитные гейты унитарны и физически корректны.
- Логика отложенного измерения (`_measurements_are_terminal`) —
  корректна.

## Новые тесты

- `qsim/test_physics.py` — сверка каждого билдера гейтов
  (`h`, `x`, `rz`, `cx`, `cz`, `swap`, `ccx`, `cswap`, `mcx`, `control`
  с произвольной перестановкой control/target) с независимыми
  эталонами, плюс статистические тесты сэмплирования (Bell/GHZ,
  сумма вероятностей).
- `qsim/test_bugfixes.py` — по одному (или несколько) регрессионному
  тесту на каждый пункт из списка выше.
